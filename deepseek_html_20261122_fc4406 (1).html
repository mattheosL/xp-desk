if-project API #

API REST para gerenciamento de projetos, quadros, colunas, tarefas e subtarefas — modelo inspirado em ferramentas de kanban (Trello). Construída com Spring Boot, persistência via Spring Data JDBC e JdbcClient/JdbcTemplate sobre PostgreSQL, autenticação via JWT Bearer com refresh token de uso único e migrations versionadas com Flyway.

Autenticação via JWT Bearer Todos os endpoints protegidos usam Authorization: Bearer <accessToken>. O antigo header X-User-Id não é mais aceito como autenticação. Login em POST /api/v1/auth/login e renovação em POST /api/v1/auth/refresh — veja Auth.
Rotas normalizadas Todos os recursos publicam sob /api/v1. Os antigos /task (singular, sem prefixo) e /api/v1/task_group passam a ser /api/v1/tasks e /api/v1/task-groups. O endpoint GET /task/test foi removido.
Swagger / OpenAPI O projeto inclui springdoc-openapi-starter-webmvc-ui. Com a aplicação em execução, a interface fica em /swagger-ui/index.html e o JSON em /v3/api-docs. Os endpoints públicos são /swagger-ui/**, /v3/api-docs/**, /error, POST /api/v1/users, POST /api/v1/users/login, POST /api/v1/auth/login e POST /api/v1/auth/refresh.

Como executar #

1. Pré-requisitos

  • JDK 25+ (toolchain declarada no build.gradle)
  • PostgreSQL em execução

Configuração atual do datasource

spring:
  application:
    name: postgres
  datasource:
    url: jdbc:postgresql://localhost:5432/if-project
    username: postgres
    password: postgres
  sql:
    init:
      mode: never
  flyway:
    baseline-on-migrate: true

app:
  jwt:
    secret: "${JWT_SECRET:if-project-dev-secret-key-change-me-32b+}"
    expiration: 24h
    refresh-expiration: 30d
  cors:
    allowed-origins: ${CORS_ALLOWED_ORIGINS:http://localhost:5173,http://localhost:3000,http://127.0.0.1:5173,http://127.0.0.1:3000}

2. Criar o schema

Flyway aplica automaticamente Com flyway-database-postgresql no classpath e spring.sql.init.mode=never, o schema é criado/migrado pelo Flyway no startup. As migrations ficam em src/main/resources/db/migration. 
# crie o banco uma única vez
createdb -U postgres if-project

# o Flyway aplica V1, V2, V3 no próximo bootRun

3. Subir a aplicação

# Windows
gradlew.bat bootRun

# Linux / macOS
./gradlew bootRun

Aplicação em http://localhost:8080 · Swagger UI em http://localhost:8080/swagger-ui/index.html.

4. Autenticar e testar

# 1) Criar usuário (endpoint público — retorna 201)
curl -X POST http://localhost:8080/api/v1/users ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"thiago\",\"email\":\"thiago@ifce.edu.br\",\"password\":\"1234\"}"

# 2) Login — obtenha accessToken + refreshToken
curl -X POST http://localhost:8080/api/v1/auth/login ^
  -H "Content-Type: application/json" ^
  -d "{\"email\":\"thiago@ifce.edu.br\",\"password\":\"1234\"}"

# 3) Chamar endpoint protegido
curl http://localhost:8080/api/v1/projects ^
  -H "Authorization: Bearer <accessToken>"

# 4) Renovar tokens
curl -X POST http://localhost:8080/api/v1/auth/refresh ^
  -H "Content-Type: application/json" ^
  -d "{\"refreshToken\":\"<refreshToken>\"}"

Autenticação e contexto #

A identidade do requisitante é transportada por um JWT Bearer (accessToken de curta duração) + refreshToken de uso único. O antigo header X-User-Id não é mais aceito.

ItemDescrição
AuthorizationBearer <accessToken> — obrigatório em endpoints protegidos
accessTokenJWT HMAC emitido no login; subject = UUID do usuário; expiração configurável (expiresIn em segundos)
refreshTokenToken opaco (48 bytes Base64URL). Persistido como SHA-256 em refresh_tokens, com expires_at e revoked_at. Uso único
JWT_SECRETVariável de ambiente obrigatória em produção (fallback em dev)
JwtAuthenticationFilterLê o header, valida o JWT, popula SecurityContext e vincula UserLogged.USER_ID via ScopedValue
UserLogged.id()Retorna o UUID corrente; lança UnauthenticatedException (401) se não houver contexto
Login legadoPOST /api/v1/users/login está @Deprecated; novos clientes devem usar POST /api/v1/auth/login
Respostas para falhas de autenticação Token ausente → 401 Unauthorized com "Não autenticado" (via authenticationEntryPoint). Token inválido/expirado → 401 com "Token inválido ou expirado" (escrito pelo filtro). Sem permissão → 403 com "Você não tem permissão para esta ação".
Migração MD5 → BCrypt transparente Senhas novas usam BCrypt. Contas antigas gravadas com MD5 (32 hex chars) são aceitas no primeiro login e regravadas automaticamente como BCrypt. 
GET /api/v1/projects
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
Content-Type: application/json

Observações técnicas #

Notas sobre comportamentos, decisões de implementação e armadilhas conhecidas.

1. Contrato unificado de autenticação POST /api/v1/auth/login é o endpoint principal. POST /api/v1/users/login permanece com @Deprecated(since = "1.0", forRemoval = false) por compatibilidade — mesmo payload e mesmo retorno.
2. Migração MD5 → BCrypt transparente AuthenticateUser primeiro tenta PasswordEncoder.matches (BCrypt). Se falhar e o hash armazenado casar com o padrão hex 32 caracteres (legado MD5), a senha em texto é validada contra MD5 e o hash é regravado com passwordEncoder.encode. Após o primeiro login válido, a conta passa a usar apenas BCrypt.
3. Owner é sempre OWNER FindProjectSQL força role = OWNER no DTO quando owner_id == userId, mesmo se o registro em project_members estiver ausente. A criação de projeto também insere o criador como OWNER em project_members na mesma transação.
4. Typo preservado — isAchived O DTO TaskResponse mantém o campo isAchived (com o erro de grafia) por compatibilidade. Qualquer alteração futura deve ser considerada como quebra de contrato.
5. Prioridade como String no modelo Em tasks, a coluna priority é VARCHAR(20) com CHECK IN ('LOW','MEDIUM','HIGH'). A entidade Task expõe o campo como String (não enum), e a validação de valor só ocorre no banco. Já em subtasks (conversão), o DTO usa o enum Priority.
6. GET /subtasks/task-groups/{taskId} Retorna sempre uma lista JSON, inclusive vazia. A ordenação é por position e, em empate, por created_at.
7. Conversão de subtarefa com reindexação Ao converter uma subtarefa em tarefa, além de inserir no fim da coluna e remover a subtarefa original, as subtarefas restantes da mesma tarefa-mãe são reindexadas (position - 1 WHERE position > ?), preservando a sequência sem lacunas.
8. CORS configurável Origens controladas por app.cors.allowed-origins em application.yaml (com override por CORS_ALLOWED_ORIGINS). Default em dev: Vite (5173) e 3000, tanto em localhost quanto em 127.0.0.1.
9. OpenAPI com Bearer O bean OpenApiConfig registra o esquema bearer-jwt em /v3/api-docs, permitindo autenticar direto no Swagger UI.
10. GET /tasks/test removido O antigo endpoint de verificação não existe mais. A contagem de tasks caiu de 5 para 4 endpoints.
11. Sem migrations destrutivas As três migrations usam CREATE TABLE IF NOT EXISTS / ON CONFLICT, então podem rodar contra bases já populadas sem perda de dados. O schema.sql continua como espelho, mas não é executado (spring.sql.init.mode=never).
